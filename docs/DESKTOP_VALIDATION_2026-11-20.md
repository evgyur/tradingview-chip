# TradingView Desktop live qualification — 2026-11-20

Environment: Windows, TradingView Desktop 3.5.1 MSIX, local CDP on 127.0.0.1:9223, current local source. These results apply to this installation and are not a claim that every registered tool or other Desktop version works.

## Observed

- Fresh launch from the installed executable and later verified reuse: Desktop-reported user agent and loopback debugger URL. The launcher does not attest the process binary or establish safety against a hostile local process.
- An initial saved-layout copy exposed mismatches between active/inactive pane projections and viewport-dependent inputs. The updated comparison uses one facade per pane and distinguishes confirmed viewport inputs from user-configurable inputs.
- On a disposable test copy: change symbol, daily timeframe, chart type and back; read loaded OHLCV; add RSI, read/change length, hide/show, remove; create a horizontal line, change visibility and remove. The original visibility attempt took effect but timed out because `isVisible` was unavailable; the fixed adapter separately verified hide/show and removal using an explicit boolean `getProperties().visible`.
- Save returned a clean layout and independently listed the saved symbol and timeframe. A subsequent `layout_open` reused the open tab rather than proving a fresh reload.
- Initial read-only probe: 17 of 19 calls returned. After fixes, replay status worked and study-template listing returned 65 templates on this account. Replay start, one-bar step, autoplay on/off with speed change, and stop were independently verified on the disposable layout; simulated trading was not tested.
- Alert prepare returned ready. Three uniquely keyed paused price-alert creation attempts, including changed native-format fields, were rejected with `invalid_request`. Exact-name reads found no matching test alerts after each attempt. No creation or delivery is claimed; uncertain mutations require reconciliation before retry. Alert history was fixed to use the native POST shape and returned five records.
- Pine `save_new` initially returned unverified because TradingView converted LF to CRLF. After restricting verification to uniform LF/CRLF conversion and reporting both hashes, a second disposable script saved and verified successfully; both test scripts were deleted by exact ID, version and saved-source hash. Other source changes remain rejected.
- Opening the Pine editor and CDP screenshot capture failed while the Desktop window was minimized. After the window was restored, the editor opened with verified visible binding, its source was read, and a PNG screenshot was captured. This establishes those operations on the restored window only. The first compiler attempt added the test indicator but reported unverified; after fixing reconciliation, a second disposable saved script compiled and the exact new chart entity was independently verified. Both disposable scripts and indicators were deleted by exact IDs. Strategy backtesting remains unqualified.
- `pine_check` was tested with valid and invalid scripts after adapting to TradingView light-validation responses: valid returned validation passed with compilation explicitly unknown; invalid returned a diagnostic. This is distinct from the chart compilation test above.
- Watchlist list/get/import preview returned without mutation. No watchlist was created or changed. Market depth was unavailable without an open panel.
- Desktop 3.5.1 initially rejected CDP /json/new. Its legacy clone handler also opened a tab asynchronously, producing a race. The updated fixed native clone request does not invoke that delayed opener; it opens and verifies one target. A fresh three-pane copy returned chart_verified and saved_configuration_verified, with unchanged saved source and zero observable chart mismatches; retry with the same key reused the same copy and left exactly one tab. A separate bounded native inventory check verified the same saved drawing IDs, counts and per-bucket sizes. Fifteen inaccessible live study-property fields remain unverified; saved layout content and metadata were compared independently. The full content of every archived drawing was not compared, so full fidelity is not claimed.
- The complete local Node test suite, `npm run check` (189 registered tools), and `npm run audit:source` passed. These checks do not establish live compatibility for every registered tool.

## Test scope and cleanup

Mutations were confined to an isolated test layout. Temporary scripts, added test indicators, and follow-up copy-verification layouts were removed by exact ID. The main disposable layout was retained for continued testing. No broker order or trade was submitted. Account-specific object IDs, names, paths and raw responses are omitted from this public report.
